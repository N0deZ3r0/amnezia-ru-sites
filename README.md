## Зачем это нужно

Банки, Госуслуги, маркетплейсы и многие другие российские сервисы плохо работают с зарубежных IP или вовсе
блокируют их. Чтобы они открывались напрямую, а остальной трафик шёл через VPN, в Amnezia есть раздельное
туннелирование. Осталось где-то взять список сайтов, а вносить сотни доменов вручную никто не хочет.

---

## Как подключить списки

1. Скачайте нужный файл (см. раздел [«Скачать»](#скачать)).
2. В Amnezia откройте **Настройки → Раздельное туннелирование → Сайты**.
3. Выберите режим **«Сайты из списка не открывать через VPN»**: тогда эти сайты пойдут напрямую,
   а всё остальное через VPN.
4. Через меню справа вверху выберите **Импорт** и укажите скачанный файл.

Названия пунктов могут немного отличаться в разных версиях клиента. Если в списке уже были записи, а вы
меняете один список на другой, сначала очистите старый, иначе записи сложатся.

Обновляйте список в клиенте раз в несколько недель: скачайте свежий файл и импортируйте его заново.

## Автообновление

Списки пересобирает GitHub Actions: каждый понедельник (в 07:00 по Москве) запускается
[`update.yml`](.github/workflows/update.yml), собирает свежие данные и коммитит файлы в `lists/`, если что-то
изменилось. Вручную сборку можно запустить во вкладке **Actions → Обновление списков → Run workflow**.

Автосборка делает то же самое, что вы можете сделать у себя (см. [«Как это устроено»](#как-это-устроено)),
и защищена от неудачных запусков:

- **Контроль размера.** Если новый список вышел меньше старого более чем на 10% (не ответили источники
  или DNS), он не записывается, а сборка завершается ошибкой. Старые списки остаются как были.
- **Перед сборкой прогоняются тесты.** Если они упали, списки не трогаются.
- **Файлы не меняются впустую.** IP в списках отсортированы, поэтому, если адреса те же, коммита не будет.

Сборка идёт на серверах GitHub, а не в России. Для проверки сравнили автосборку с локальной сборкой из
России: 99% доменов в списках совпали. Но часть сайтов отдаёт разные адреса в зависимости от страны
запроса, поэтому, если важна точность под ваш регион, пересоберите списки у себя
(см. [«Обновить у себя»](#обновить-у-себя)).

## Обновить у себя

Нужен [Python](https://www.python.org/downloads/) 3.8 или новее (при установке отметьте **Add Python to PATH**).

```cmd
pip install dnspython
python update.py
```

Или просто дважды щёлкните по `update.cmd`: он сам поставит `dnspython`, запустит сборку и оставит окно
открытым до нажатия клавиши.

> [!IMPORTANT]
> Запускайте при **выключенном VPN и прокси**. Иначе DNS отдаст адреса, которые видны через туннель, а не
> те, что нужны для прямого подключения.

Другие размеры списков задаются параметром `--sizes`:

```cmd
python update.py --sizes 500,2000
```

Чтобы не затереть хорошие списки плохой сборкой, добавьте `--min-ratio 0.9`: если новый список
получится меньше старого более чем на 10%, файлы не будут перезаписаны.

## Как это устроено

1. **Сбор доменов.** `harvest_ru.py` скачивает публичные рейтинги сайтов
   ([Tranco](https://tranco-list.eu), [Majestic Million](https://majestic.com/reports/majestic-million),
   Cisco Umbrella) и оставляет из них `.ru`. Порядок сохраняется: чем популярнее сайт, тем он выше.
2. **Резолвинг.** Каждый домен опрашивается дважды через несколько DNS-серверов (Яндекс, Google, Cloudflare),
   чтобы собрать больше адресов, ведь у больших сайтов их несколько.
3. **Фильтр «только российские IP».** Скачивается список российских диапазонов адресов
   ([ipdeny.com](https://www.ipdeny.com), запасной источник на GitHub), и всё, что в него не входит,
   отбрасывается. Так в список не попадают Cloudflare, AWS и другие зарубежные адреса, которые нельзя
   отправлять в обход VPN.
4. **Нарезка.** `make_lists.py` берёт первые N доменов и убирает IP, которые уже встречались у более
   популярных сайтов: клиент добавляет маршрут на каждый адрес, повторы только замедляют подключение.

Каждый шаг можно запускать отдельно:

```cmd
python harvest_ru.py --limit 5000 -o data/amnezia_sites.json
python make_lists.py data/amnezia_sites.json -n 300 -n 1000 -o lists
```

Полезные параметры `harvest_ru.py` (список всех: `python harvest_ru.py -h`):

| Параметр | Что делает |
|---|---|
| `--limit N` | Взять только первые N доменов. `update.py` по умолчанию берёт втрое больше самого большого списка |
| `--extra файл.txt` | Добавить свой список доменов, по одному в строке |
| `--tld ru,xn--p1ai` | Собирать ещё и домены `.рф` |
| `--keep-foreign` | Не отфильтровывать зарубежные IP |
| `--dns 77.88.8.8,8.8.8.8` | Свои DNS-серверы |
| `--no-tranco`, `--no-majestic`, `--no-umbrella` | Отключить источник |

## Честно о пределах

- **Больше не значит лучше.** Клиент добавляет в систему маршрут на каждый IP. Полный список на 35 тысяч
  доменов (около 40 тысяч адресов) приводит к тому, что Amnezia зависает на подключении. Список на 1000
  доменов работает нормально. Где именно проходит граница, зависит от клиента и системы: если
  `top1000` зависает, берите `top300`.
- **Это не весь `.ru`.** В зоне около пяти миллионов доменов, и открытого списка нет. Рейтинги дают самые
  посещаемые сайты, а редкие и новые в списки не попадут.
- **Страна определяется по базе диапазонов.** Российский сайт на зарубежном CDN в список не попадёт, а
  сайт на российском хостинге попадёт. Для сайтов за общими адресами (CDN) маршрутизация по IP вообще
  работает неточно.
- **Списки устаревают.** Сайты переезжают на другие адреса. Автообновление раз в неделю это смягчает,
  но не отменяет: если что-то перестало открываться напрямую, обновите список в клиенте.

## Состав репозитория

| Файл | Назначение |
|---|---|
| `lists/` | Готовые списки `amnezia_top300.json` и `amnezia_top1000.json` (обновляются автоматически) |
| `.github/workflows/update.yml` | Еженедельное автообновление списков |
| `.github/workflows/check.yml` | Проверка кода и тестов при каждом изменении |
| `update.py`, `update.cmd` | Обновление списков одной командой |
| `harvest_ru.py` | Сбор доменов и резолвинг |
| `make_lists.py` | Нарезка полного списка на topN |
| `tests/test_offline.py` | Проверки без сети (DNS подменяется заглушкой) |

Проверки: `python -m unittest discover -s tests -v`.
